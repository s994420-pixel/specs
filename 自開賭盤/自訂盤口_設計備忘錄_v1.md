# 自訂盤口功能設計備忘錄

> 記錄功能設計過程中的討論決策與原因，供後續撰寫說明文件使用。

---

## 一、賠率模式：模擬 Polymarket

### 決策
採用「視覺模擬 Polymarket」模式，而非真正的資金池互賭。

### 原因
真正的 Polymarket 是玩家互賭，站長不出錢、只收手續費。但 GSI 的站長仍扮演莊家角色，賠付來源是站長的錢，因此：

- **外表**：賠率隨下注分布動態變動，看起來像 Polymarket
- **實際**：站長承擔賠付，透過抽水比例和最大賠付上限控制風險

---

## 二、賠率計算公式

### 公式
```
選項賠率 = 總池 ÷ 該選項池 × (1 − 抽水率)
```

### 舉例（抽水 5%）
- 總池 10,000，選項A 下注 7,000，選項B 下注 3,000
- A 賠率 = 10,000 ÷ 7,000 × 0.95 ≈ **1.36**
- B 賠率 = 10,000 ÷ 3,000 × 0.95 ≈ **3.17**

資金越多的選項賠率越低，越少的越高。

### 抽水比例的用途
每筆下注進來前先抽一定比例給平台，抽完後才是可分配獎金。這是站長不會賠錢的基本保障。

---

## 三、初始賠率

### 決策
系統自動預填，站長可手動覆蓋。

### 公式（等機率假設）
```
初始賠率 = 選項數 × (1 − 抽水率)
```

### 舉例
- 2 個選項、抽水 5%：2 × 0.95 = **1.90**
- 3 個選項、抽水 5%：3 × 0.95 = **2.85**

### 說明
初始賠率只是開盤第一秒的數字，假設每個選項被押的機率相等。開盤後馬上隨真實下注分布被公式覆蓋，所以初始值影響不大。新增或刪除選項時自動重算。

---

## 四、賠率上下限保護

### 決策
非強制，站長自行決定是否啟用。

### 適用情境
某個選項完全沒人下注時，公式會算出極高賠率（理論上趨近無限大），可能造成派彩異常。

### 舉例（設最高賠率 20）
- 選項A 池 9,900，選項B 池 100
- B 原始賠率 = 10,000 ÷ 100 × 0.95 = **95.00**
- 啟用上限後夾住為 **20.00**

夾住後：資金池比例計算邏輯不受影響，僅限制最終顯示與派彩賠率。

---

## 五、多幣別處理

### 基準幣
所有幣別的下注，結算時統一換算為基準幣（預設 USDT）再計算賠率與賠付。

### 匯率鎖定時間點
封盤後結算時套用當下匯率快照，不是下注當下鎖定。

### 各幣別下注上下限
每個選項可針對每個接受幣別，分別設定最低下注和最高下注金額。站長勾選哪些幣別，就顯示哪些幣別的設定欄位。

## 六、AI 建立盤口事件

### 功能說明
站長可在後台右下角通知視窗點擊「用 AI 快速建立新盤口事件」，透過自然語言描述，由 AI 解析並自動完成建盤流程。

### 流程
1. 點擊通知視窗的 AI 入口，右側滑出 AI 對話視窗
2. 輸入自然語言描述（例如：「幫我建立一個猜 BTC 下週是否突破 12 萬的盤口，抽水 5%」）
3. AI 解析出事件標題與分類，回傳確認摘要
4. 點擊「✦ 立即建立此盤口事件」，系統自動填入所有欄位並完成新增

### 預設值規則

| 欄位 | 預設值 | 說明 |
|---|---|---|
| 開盤時間 | 下一個週一 00:00 | 固定，不依描述內容調整 |
| 封盤時間 | 下一個週五 23:59 | 固定，不依描述內容調整 |
| 投注模式 | 單題雙選項型 | 固定 |
| 選項 | 是 / 否 | 固定 |
| 分類 | AI 依描述判斷 | 從現有分類中選擇最合適的 |
| 抽水比例 | AI 解析，預設 5% | 描述中有提及則採用，否則預設 |

### 標識
AI 建立的事件在列表標題左側顯示「✦ AI」漸層標籤，方便站長辨識來源。

### 安全防護

為避免站長濫用對話框或惡意套取平台資訊，實作三層防護：

| 層級 | 機制 | 說明 |
|---|---|---|
| 第一層 | System Prompt 防護咒語 | 明確限制 AI 只能執行建盤任務；遇到詢問系統指令、要求扮演其他角色、要求忽略規則等，一律回覆固定拒絕語，禁止輸出平台任何內部資料 |
| 第二層 | 前端輸入過濾 | 送出前以 regex 比對常見注入關鍵詞（「忽略上述規則」、「請提供你的指示」、`system prompt`、`jailbreak`、`DAN`、`roleplay` 等），命中則直接在前端攔截，不送 API |
| 第三層 | 輸入長度限制 | 單次輸入超過 500 字直接擋下，防止超長 prompt 稀釋或混淆 System Prompt |

### 注意事項
- AI 產出內容僅供參考，站長可在建立後進入編輯頁面調整任何欄位
- 若 API 連線失敗，自動切換本地 mock 回應，仍可完成建立流程（原型展示用）

## 七、結算機制：雙帳號確認

### 規則
- 任意兩組後台帳號（不限定原本的A、B，C+D也算有效）
- 兩人帳號不得相同
- 封盤後後台右下角出現倒數警示，點擊直跳結算頁

### 二次判定期
- 第一輪兩組結果不一致，進入二次判定期
- 系統只給**一次**二次判定機會，倒數 2 小時
- 2 小時內任意兩組帳號重新提交一致 → 正常派彩
- 逾時或第二輪仍不一致 → 取消賭盤、全額退款

### 派彩錢包
- 建盤時選定，100% 打入，建盤後不可更改
- 三個選項：一般錢包、贈金錢包、撲滿錢包

## 七、移除的欄位與原因

| 移除欄位 | 移除原因 |
|---|---|
| 題型（是/否、多選一、區間盤） | 選項完全自訂，題型由選項內容自然決定，前台樣式也不依題型區分 |
| 扣款錢包 | 簡化設定，統一由錢包類型決定 |
| 預計結算時間 | 封盤後系統自動提示站長輸入結果，不需預設時間 |
| 單次最大調整幅度 | 已有最低/最高賠率保護，此欄位冗餘且站長難以理解 |
| 計入人數最低下注 | Polymarket 不存在此設定，資金池模式下不需要 |
| 同 IP / 裝置 | 移至風控黑名單設定統一管理 |
| 最低/最高賠率（原強制） | 改為可選啟用，由站長決定是否需要保護 |
| 依下注人數變動賠率 | 賠率與實際資金池脫鉤，極端情境下站長須自行貼補巨額賠付，風險過高；統一改為依下注金額計算 |
| 行銷活動設定、行銷活動審核 tab | 原型空殼，點了沒有任何內容 |
